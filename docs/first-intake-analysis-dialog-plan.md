# Первый приём (Анализ): план переделки раздела самоанализа

Дата: 2026-06-18

## 1. Задача

Переделать раздел сайта **«Сделать самоанализ»** в раздел **«Первый приём (Анализ)»**.

Главная идея: пользователь не должен ощущать, что он заполняет сухую анкету. Экран должен работать как мягкое окно первичного общения с терапевтом: терапевт задаёт короткий вопрос, пользователь выбирает ответ или добавляет короткий комментарий, система ведёт его через несколько шагов и в конце показывает предварительное понимание ситуации.

Важно: это не медицинская диагностика и не обещание лечения. Формулировки должны оставаться в логике поддержки: «прояснить состояние», «увидеть главный узел», «подготовить материал для специалиста», «может быть полезно проверить».

## 2. Что найдено в коде

В текущем репозитории рабочая архитектура кабинета собрана вокруг Profile Lite:

- `src/main.jsx` — маршрутизация на `/profile`, `/profile-lite`, `/profile/mandalas`, `/profile/services`, `/profile/orders`, `/profile/chats`, `/profile/settings`.
- `src/lib/profileLiteClient.js` — список вкладок `PROFILE_LITE_TABS`, route mapping и helper-функции для активной вкладки.
- `src/pages/profile-lite/ProfileLiteShell.jsx` — оболочка кабинета, верхняя навигация вкладок и общий layout.
- `src/pages/ProfileLitePage.jsx` — основной контейнер состояния, загрузки профиля, module props и выбор модуля через объект `renderedModule`.
- `src/profileCabinet.css` — базовый стиль кабинета: тёплый фон, карточки, кнопки, сетки.

Тексты из скриншота (`Holistic Therapy Cabinet`, `Сделать самоанализ`, `Комментарий специалиста`) в текущей версии репозитория не находятся через GitHub code search. Поэтому реализацию нужно делать как новый модуль в существующей архитектуре Profile Lite или адаптировать к фактическим файлам текущей рабочей ветки, если у локального Codex есть ещё не запушенная версия с этим экраном.

## 3. Куда лучше вставить

Рекомендуемая архитектура: добавить отдельный модуль **intake / first-intake** рядом с существующими модулями Profile Lite.

### 3.1. Новый компонент

Создать файл:

```txt
src/pages/profile-lite/ProfileLiteFirstIntakeModule.jsx
```

Назначение файла: только UI и локальная логика диалога первого приёма.

Почему отдельный файл:

- не раздувает `ProfileLitePage.jsx`, который уже является большим контейнером;
- проще тестировать;
- проще позже подключить сохранение в Supabase;
- можно независимо дорабатывать сценарии вопросов.

### 3.2. Подключение во вкладки

Изменить:

```txt
src/lib/profileLiteClient.js
```

В `PROFILE_LITE_TABS` добавить новую вкладку первой в списке:

```js
{ id: "first-intake", label: "Первый приём (Анализ)", href: "/profile?tab=first-intake" }
```

Лучше поставить её перед `mandalas`, чтобы это был первый рабочий пункт в кабинете.

Обновить `getProfileLiteInitialTabFromLocation`, если будет отдельный route:

```js
"/profile/first-intake": "first-intake"
```

Минимальный вариант без нового route: использовать `/profile?tab=first-intake`.

### 3.3. Подключение в `ProfileLitePage.jsx`

В `src/pages/ProfileLitePage.jsx`:

1. Добавить импорт:

```js
import ProfileLiteFirstIntakeModule from "./profile-lite/ProfileLiteFirstIntakeModule.jsx";
```

2. В объект `renderedModule` добавить:

```jsx
"first-intake": <ProfileLiteFirstIntakeModule {...moduleProps} />,
```

Поставить рядом с `overview` / `profile`, до `mandalas`.

### 3.4. CSS

Лучше добавить стили в:

```txt
src/profileCabinet.css
```

Новые классы делать с префиксом:

```css
.profileLiteFirstIntake
.firstIntakeLayout
.firstIntakeChat
.firstIntakeBubble
.firstIntakeAnswerGrid
.firstIntakeSummary
```

Так не будет конфликта с уже существующими модулями.

## 5. Сценарий диалога

Диалог должен идти пошагово. На каждом шаге показывается:

- короткая реплика терапевта;
- 4–6 вариантов ответа;
- опциональное поле «добавить своими словами»;
- индикатор прогресса: `Шаг 1 из 6`.

### Шаг 1. Главный фокус

Реплика:

```txt
Смотрю на вашу текущую ситуацию. С чего лучше начать: что сейчас сильнее всего беспокоит?
```

Варианты:

```txt
Физическое состояние / симптомы
Эмоции и тревога
Усталость / нет сил
Отношения / контакт с людьми
Работа / деньги / реализация
Не понимаю, что происходит
```

Поле данных: `mainConcern`.

### Шаг 2. Где это ощущается

Реплика:

```txt
Где это сейчас ощущается сильнее всего?
```

Варианты:

```txt
Голова / напряжение
Грудь / дыхание
Живот / пищеварение
Кожа / воспаление
Общая слабость
В отношениях / контакте
В мыслях / невозможности решить
Другое
```

Поле данных: `feltArea`.

### Шаг 3. Сила состояния

Реплика:

```txt
Насколько это сейчас сильно, если смотреть честно по последним дням?
```

Варианты:

```txt
1–3: слабо, но заметно
4–6: мешает жить
7–8: сильно захватывает
9–10: почти невозможно выдерживать
```

Поле данных: `intensity`.

### Шаг 4. Что усиливает

Реплика:

```txt
Что обычно усиливает это состояние?
```

Варианты:

```txt
Стресс / спешка
Конфликт / давление
Одиночество
Усталость / недосып
Страх оценки
Неопределённость
Не знаю
```

Поле данных: `trigger`.

### Шаг 5. Что облегчает

Реплика:

```txt
Что хотя бы немного облегчает состояние?
```

Варианты:

```txt
Отдых
Поддержка другого человека
Тепло / тело / прикосновение
Понимание причины
Природа / прогулка
Структура и план
Пока ничего
```

Поле данных: `relief`.

### Шаг 6. Что пользователь хочет получить

Реплика:

```txt
Что было бы самым полезным результатом первого приёма?
```

Варианты:

```txt
Понять главную причину состояния
Получить короткий план поддержки
Понять, какой отчёт нужен специалисту
Определить, что проверить дальше
Просто собрать состояние в ясную картину
```

Поле данных: `desiredOutcome`.

## 7. Локальная модель данных

В первом PR достаточно локального состояния без Supabase.

```js
const FIRST_INTAKE_INITIAL_ANSWERS = {
  mainConcern: "",
  feltArea: "",
  intensity: "",
  trigger: "",
  relief: "",
  desiredOutcome: "",
  notes: {}
};
```

Состояния компонента:

```js
const [currentStep, setCurrentStep] = useState(0);
const [answers, setAnswers] = useState(FIRST_INTAKE_INITIAL_ANSWERS);
const [isStarted, setIsStarted] = useState(false);
const [isComplete, setIsComplete] = useState(false);
```

Структура шагов:

```js
const FIRST_INTAKE_STEPS = [
  {
    id: "mainConcern",
    title: "Главный фокус",
    therapistText: "Смотрю на вашу текущую ситуацию. С чего лучше начать: что сейчас сильнее всего беспокоит?",
    options: ["Физическое состояние / симптомы", "Эмоции и тревога", "Усталость / нет сил", "Отношения / контакт с людьми", "Работа / деньги / реализация", "Не понимаю, что происходит"]
  }
];
```

Для каждого шага после выбора:

```js
setAnswers((current) => ({ ...current, [step.id]: option }));
setCurrentStep((value) => Math.min(value + 1, FIRST_INTAKE_STEPS.length));
```

На последнем шаге:

```js
setIsComplete(true);
```

## 8. Важная логика UX

1. Пользователь должен видеть уже выбранные ответы как маленькие клиентские пузырьки.
2. Текущий вопрос терапевта должен быть визуально главным.
3. После выбора ответа не должно быть перезагрузки страницы.
4. Должна быть кнопка «Назад», чтобы поправить предыдущий ответ.
5. Должна быть кнопка «Начать заново».
6. Поле «добавить своими словами» не должно быть обязательным.
7. Нельзя использовать слова: «диагноз», «лечение гарантировано», «вылечим», «назначение препарата».
8. Можно использовать: «прояснить», «предварительное понимание», «требует проверки», «поддержка», «рабочая гипотеза».

## 9. Текстовый тон

Тон — живой, спокойный, терапевтический.

Хорошо:

```txt
Смотрю.
Давайте начнём с самого сильного.
Отвечайте как есть сейчас.
Здесь важно не идеальное описание, а точка входа.
```

Плохо:

```txt
Заполните форму.
Укажите симптоматику.
Рекомендуется осуществлять мониторинг.
Данный раздел предназначен для сбора анамнеза.
```

## 14. Критерий готовности

Готово, если:

1. В навигации появился первый пункт `Первый приём (Анализ)`.
2. Экран больше не выглядит как анкета самоанализа.
3. Центральный блок выглядит как терапевтический диалог.
4. Есть 6 шагов вопросов.
5. Выбор ответа переводит на следующий шаг без перезагрузки.
6. Есть «Назад», «Начать заново», финальный summary.
7. Правая колонка объясняет, как отвечать.
8. Нет медицинских диагнозов, обещаний исцеления и назначений лечения.
9. Существующие вкладки Profile Lite не ломаются.
10. `npm run test:profile-lite` и `npm run build` проходят.
