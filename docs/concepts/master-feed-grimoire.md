# Концепция: кабинет мастера как лента практиков и Гримуарий

Дата: 2026-06-05  
Проект: Reiki Yggdrasil  
Repo: `andylitvinov-design/reiki-yggdrasil`  
Рабочий live URL: `https://mentalica.vercel.app`  
Legacy/current URL до полной проверки миграции: `https://reiki-yggdrasil.vercel.app`  
Статус документа: product concept / needs implementation planning

## 1. Суть идеи

Если Reiki Yggdrasil развивается как сеть практиков, кабинет мастера должен быть не просто формой профиля или технической админкой, а живой личной лентой практики.

Мастер должен легко публиковать:

- новые мандалы;
- настройки;
- материалы;
- фотографии;
- заметки;
- гримуарные записи;
- услуги;
- результаты практик.

По ощущению это должно быть ближе к Facebook/Instagram-ленте, но не как развлекательная социальная сеть, а как профессиональная магическая мастерская, где каждый опубликованный объект можно дальше разобрать, оформить и использовать в Гримуарии.

## 2. Главная продуктовая модель

Кабинет мастера состоит из трёх смысловых зон:

1. Левая колонка — навигация и фильтры.
2. Центральная колонка — лента мастера.
3. Правая колонка — быстрые действия, загрузчик и неразобранные материалы.

Эта модель должна сохранять существующее правило проекта: desktop three-column layout не ломать.

## 3. Центральная лента мастера

Центральная часть кабинета должна отвечать на вопрос:

> Что нового создал, загрузил или опубликовал мастер?

Вверху ленты нужен блок быстрого создания, похожий на социальную сеть:

```text
Что вы хотите добавить в свою мастерскую?

+ Мандала
+ Фото / материал
+ Настройка
+ Запись в гримуар
+ Услуга
```

Ниже отображаются карточки публикаций.

## 4. Типы публикаций

В ленте могут быть разные типы объектов:

### 4.1. Мандала

- мандала места силы;
- мандала клиента;
- мандала курса;
- мандала услуги;
- личная диагностическая мандала.

### 4.2. Настройка

- энергетическая настройка;
- Reiki Yggdrasil initiation;
- ритуальная практика;
- короткое описание способа передачи энергии;
- настройка для курса или услуги.

### 4.3. Материал

- статья;
- фото;
- PDF;
- заметка;
- скрин;
- изображение артефакта;
- текстовая заготовка;
- later: аудио/видео.

### 4.4. Гримуарная запись

- личное наблюдение;
- комментарий к материалу;
- символический разбор;
- описание действия мандалы;
- ритуальная инструкция;
- связь материала с архетипом, стихией, курсом или услугой.

### 4.5. Услуга

- опубликованная мандала как услуга;
- описание услуги;
- клиентская ссылка;
- кнопка редактирования описания;
- связь с публичным профилем мастера.

## 5. Карточка публикации

Каждая карточка в ленте должна иметь понятную структуру:

### Шапка

- имя / профиль мастера;
- дата создания или обновления;
- тип объекта: `Мандала`, `Материал`, `Настройка`, `Гримуар`, `Услуга`;
- статус видимости.

### Тело

- превью изображения, если есть;
- название;
- короткий комментарий мастера;
- категория;
- теги;
- связь с мандалой/услугой/курсом, если есть.

### Действия

- `Редактировать`;
- `Добавить в Гримуарий`;
- `Опубликовать в услугах`;
- `Добавить в мастерскую`;
- `Скопировать ссылку`;
- `Удалить`.

## 6. Статусы и видимость

У объектов должны быть простые статусы:

- `draft` — черновик;
- `private` — видно только мастеру;
- `workshop` — используется в мастерской;
- `service` — опубликовано как услуга;
- `public` — доступно в публичном профиле или общей ленте later;
- `uncategorized` — загружено, но ещё не разобрано.

Важно: не делать сразу полноценную публичную социальную сеть. Первый MVP — личная лента мастера внутри `/profile`.

## 7. Левая колонка: фильтры

Левая колонка должна помогать быстро найти нужные материалы.

Базовые фильтры:

- Все;
- Мандалы;
- Фото;
- Материалы;
- Настройки;
- Гримуар;
- Услуги;
- Черновики;
- Неразобранное.

Дополнительные фильтры later:

- Для себя;
- Для клиента;
- Для курса;
- Для услуги;
- Для мастерской;
- Для публикации;
- Архив.

Тематические категории later:

- Reiki Yggdrasil;
- Места силы;
- Мандалы;
- Настройки;
- Ритуалы;
- Артефакты;
- Клиенты;
- Обучение;
- Личные заметки.

## 8. Правая колонка: быстрый загрузчик

Правая колонка должна быть рабочим инструментом, а не декоративным блоком.

На desktop загрузчик должен быть открыт по умолчанию.

Базовые действия:

- `Загрузить фото`;
- `Загрузить файл`;
- `Добавить текст`;
- `Создать мандалу`;
- `Создать настройку`.

Также нужен блок:

```text
Неразобранное
```

Туда попадают последние загруженные материалы без категории.

Кнопка:

```text
Открыть Гримуарий
```

## 9. Гримуарий

Гримуарий — это не просто архив. Это кабинет разбора материалов.

Если лента отвечает за поток:

> Я создал / загрузил / сохранил.

То Гримуарий отвечает за смысл:

> Что это значит, как это классифицировать и как использовать в практике?

В Гримуарии мастер должен иметь возможность:

- открыть любой материал;
- добавить название;
- добавить категорию;
- добавить комментарий;
- описать символику;
- описать практическое применение;
- связать с курсом;
- связать с услугой;
- связать с мандалой;
- перевести объект из `uncategorized` в рабочую категорию;
- выбрать видимость: `private`, `workshop`, `service`, `public`.

## 10. Поток работы пользователя

### Сценарий 1. Быстрая загрузка с телефона

1. Мастер открывает кабинет.
2. Нажимает `Загрузить фото / материал`.
3. Загружает сразу несколько фото, статей или скринов.
4. Все материалы попадают в `Неразобранное`.
5. Later мастер открывает Гримуарий и раскладывает материалы по категориям.

### Сценарий 2. Мандала становится услугой

1. Мастер создаёт мандалу места силы.
2. Сохраняет её в `Мои мандалы`.
3. В ленте появляется карточка мандалы.
4. Мастер нажимает `Опубликовать в услугах`.
5. Мандала появляется в разделе `Мои услуги`.
6. Мастер редактирует описание услуги.
7. Мастер копирует ссылку и отправляет клиенту.

### Сценарий 3. Настройка становится гримуарной записью

1. Мастер пишет короткое описание настройки.
2. Публикует её в ленте как `Настройка`.
3. Позже открывает в Гримуарии.
4. Добавляет символику, инструкцию, категорию и связь с курсом.
5. Настройка становится частью мастерской или курса.

## 11. Этапы реализации

### Этап 1 — личная лента мастера

Цель: сделать UI-структуру внутри `/profile`.

Минимально:

- composer в центре;
- карточки публикаций;
- фильтры слева;
- открытый загрузчик справа;
- блок `Неразобранное`;
- без полной публичной социальной сети.

### Этап 2 — связь с существующими мандалами и медиа

Цель: использовать реальные сохранённые данные, если они уже есть в Supabase.

Проверить:

- сохранённые мандалы;
- загруженные фото;
- object refs / signed URLs;
- категории материалов;
- список `Мои мандалы`;
- список `Мои услуги`.

### Этап 3 — Гримуарий

Цель: создать отдельный кабинет разбора материалов.

Возможные разделы:

- `Неразобранное`;
- `Материалы`;
- `Мандалы`;
- `Настройки`;
- `Услуги`;
- `Курсы`;
- `Архив`.

### Этап 4 — публичный профиль мастера

Цель: вывести избранные опубликованные материалы наружу.

Публично можно показывать:

- избранные мандалы;
- услуги;
- открытые настройки;
- статьи;
- профиль мастера.

### Этап 5 — общая лента практиков

Только после стабильной личной ленты можно делать общую социальную ленту:

- новые публикации мастеров;
- подписки;
- реакции;
- комментарии;
- рекомендации;
- каталог практиков.

## 12. Технические ограничения проекта

Сохранять:

- главную страницу `/`;
- RU-default interface;
- routes:
  - `/`;
  - `/profile`;
  - `/masters`;
  - `/profile/admin`;
- Supabase auth/data flows;
- Vercel rewrites;
- desktop three-column structure;
- mobile single-column fallback.

Не делать:

- не переписывать весь кабинет;
- не ломать текущие мандалы;
- не ломать текущие медиа;
- не выводить env values;
- не хранить секреты;
- не смешивать production и preview;
- не делать публичную социальную сеть раньше личной ленты.

## 15. Критерий готовности MVP

MVP считается готовым, если:

- `/profile` визуально похож на личную ленту мастера;
- есть composer для быстрых публикаций;
- есть фильтры слева;
- справа открыт загрузчик;
- есть блок `Неразобранное`;
- существующие мандалы и медиа не сломаны;
- desktop остаётся трёхколоночным;
- mobile не имеет горизонтального overflow;
- RU-интерфейс сохранён;
- build/check проходят;
- Supabase secrets не раскрыты.
